# 向主管 Codex 交回任务

由开发会话判断何时交回，shell 执行通知；不需要 DSH 插件或桌面重启。

## 何时使用

用户已要求该任务完成后通知主管，且本轮开发、适用验证、提交与 push 已完成。普通问答、阶段说明、失败退出、仅有 `turn/end` 都不是交回条件。通知不扩展原任务的修改、合码、发布或付费授权。

## 接收人

主管 thread UUID 必须**每次由本次用户指令或明确的任务绑定给出**，调用时用 `--thread` 显式传入。本 Skill 不保存、不内置、不推断任何主管对话：

- 不要把 DSH 的 sessionId、工作区名当成 Codex thread ID，不要从开发会话自己的环境变量推断主管 ID；
- 不要沿用其他任务或上一次交付的 UUID，不要从历史记录、包内文件或账本里取默认值；
- 同一条任务在后续轮次沿用该任务已明确绑定的 UUID，直到用户明确更换主管对话；
- 没有明确目标时先询问，不要自行猜测，也不要发送。

## 发通知

先保存 UTF-8 验证摘要文件，写明任务、实际通过/失败/跳过项、证据绝对路径、未验证事项及已知限制。不要写凭据或用户数据。脚本不运行测试，摘要必须来自已完成的验证。

运行本 Skill 内的脚本，路径相对本 Skill 安装目录解析：

```sh
python3 scripts/notify.py \
  --thread '<本任务主管 UUID>' \
  --repo '<任务 worktree 绝对路径>' \
  --branch '<原 PR 分支>' \
  --pr-url 'https://github.com/<owner>/<repo>/pull/<number>' \
  --summary-file '<验证摘要绝对路径>'
```

可先加 `--dry-run` 核对通知。`--thread` 是脚本必填项（缺省直接报错），脚本内没有任何默认目标；dry-run 只打印将要发送的正文，不投递、不写账本。脚本只支持当前 GitHub 工作流：校验 origin 仓库、当前分支、干净工作区和远端分支完整 SHA，生成交接正文，再调用 `codex queue`。Codex CLI 会自动探测（也可用 `--codex-bin` 或环境变量 `CODEX_BIN` 指定）；先跑 `notify.py --probe` 可以只读地确认它会用哪个 CLI、什么版本、是否支持 `queue`，不发任何东西。它不提交、push、创建 PR 或改变 Git 状态；PR 应事先存在且属于该任务。

默认账本 `~/.dsh/codex-notifications/ledger.json`，以仓库/PR/head/目标对话去重，文件锁防止并发重复发送。账本不提交到 Git。

## 看结果并交回

- `queued`：CLI 已确认排队，保留 message ID；不是主管收到/审查通过的证明。结束本轮，暂不继续修改该分支，等待审查或用户明确续作。
- `already-queued`：同一 head 已通知，停止，不重发。
- `unknown` / `blocked`：进程超时、异常退出或没收到可解析确认，可能已投递。停止重发，报告 eventId 与账本状态，核对主管历史后由人处理；不删账本绕过去重。
- 前置校验失败：修正实际问题后重新检查；不把未推送/脏工作区当成可交回成果。

新修复 push 出新 head 后可再次通知。主管 review 有问题时通过已有 DSH 投递箱交回原开发会话；本 Skill 不自行启动无限审查循环或自动合码。

## 已验证边界

本机 `codex queue` 已实测可唤醒 `--thread` 指定的对话，无需 GUI 操作。此脚本的机械行为用模拟 CLI 验证；不保证应用关闭/电脑休眠时立即执行。外部CLI与本地账本无法保证跨崩溃恰好一次，未知状态通过停止重发处理。
